# 自动发现与批量抓取

从「给我链接」升级到「自己去网上找」。目标：抓最近 N 天带贴图的帖子，
攒够指定数量。

## 为什么不能直接调搜索接口

Threads 的搜索 GraphQL（`BarcelonaSearchResultsQuery`）在匿名请求下返回
**HTML 登录墙**，不是 JSON。主页时间线的 GraphQL（`BarcelonaProfileThreadsTabDirectQuery`）
同样如此。回复翻页的 `BarcelonaPostPageDownwardQuery` 在部分 IP 上也会被拦。

但**搜索页和主页的 HTML 本身是服务端渲染的**，里面带 15-55 条帖子节点。
所以发现只能靠「反复请求页面 + 解析页面」，不能靠接口翻页。

**这条限制是 IP 信誉问题，不是代码问题。** 用登录 cookie 能解开接口，
但 cookie 会过期，且账号有风险。

## 发现链路

```
SEED_QUERIES（37 个多语言关键词）
    ↓ 搜索页，每词 20-55 帖
候选帖子（带 taken_at，按时间窗过滤）
    ↓ 抽出作者
作者主页（每人 15-50 帖）
    ↓ 再抽作者
第二轮扩散 → 第三轮 → ... 直到贴图数达标或作者池耗尽
```

实测收敛曲线（30 天窗口，16 并发）：

| 阶段 | 帖数 | 贴图数 | 作者数 | 耗时 |
|---|---|---|---|---|
| 搜索（37 词） | 26 | 725 | 339 | 9s |
| 扩散 1 轮 | 304 | 3801 | 775 | 40s |
| 扩散 3 轮 | 643 | 4510 | 2355 | 155s |
| 扩散 5 轮 | 1119 | 5369 | 5155 | 285s |
| 扩散 7 轮 | 3814 | 10401 | 19704 | ~40min |
| 扩散 9 轮（耗尽） | 7608 | 16764 | 36998 | ~70min |

**关键观察**：贴图数增长远慢于作者数。原因是大部分作者的主页里没有贴图
（`no_sticker` 占比 97%）。所以扩散是「广撒网」，效率随轮次下降。

## 两个阶段解耦

发现很慢（翻几百个主页），下载很快（24 路并发）。分开的好处：

1. 发现中断不丢成果（状态写 `discover.json`）
2. 可以先攒一大票再一次性下载
3. 下载失败可以单独重试，不用重跑发现

```bash
# 阶段一：发现（可中断续跑）
python3 -m mediafetch discover ~/work --days 30 --target 9000

# 阶段二：下载
python3 -m mediafetch fetch ~/work --archive ~/stickers
```

## 状态文件

`<work>/discover.json`：

```json
{
  "queries_done": ["sticker", "..."],
  "profiles_done": ["alice", "..."],
  "authors_pending": ["bob", "..."],
  "posts": {
    "ABC123": {
      "code": "ABC123", "author": "alice", "taken_at": 1792423380,
      "caption": "...", "stickers": [{"id": "...", "sources": ["..."]}]
    }
  },
  "stats": {"queries": 37, "profiles": 1113, "seen": 33649,
            "kept": 457, "too_old": 500, "no_sticker": 32692}
}
```

`posts` 只存精简结构（不存原始节点），文件因此只有几 MB 而不是几百 MB。

## 时间窗过滤

`--days 30` 会过滤 `taken_at` 超过 30 天的帖子。实测 7608 帖里超期的只有 5 条
（0.07%），说明搜索和主页返回的都是近期内容。

## 去重发生在两层

1. **发现层**：同一 `code` 只收一次
2. **下载层**：同一 `sticker id` 只下一次

实测：发现 16764 个贴图引用 → 去重后 7604 个唯一贴图（55% 重复率）。
同一个 giphy 贴图被几十个人转发是常态。

## 已知限制

| 限制 | 原因 | 影响 |
|---|---|---|
| 搜索不可翻页 | `page_info.has_next_page` 恒为 false | 每个关键词只有一页结果 |
| 主页不可翻页 | 同上 | 每人只能拿到最近 ~15-50 帖 |
| 扩散效率递减 | 大部分作者主页没贴图 | 到 5000 贴图后每轮只增 500-1000 |
| 需要 70 分钟 | 3.7 万个主页请求 | 想更快只能加机器或加代理 |
